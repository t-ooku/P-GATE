# HOSHILU 9モール商品提示・有効化手順

更新日: 2026-08-01

## 対象

Amazon、楽天市場、Qoo10、SHEIN、ZOZOTOWN、SHOPLIST、MUSINSA、BUYMA、SNKRDUNK。

## 現在できること

- 9モールの商品詳細URLをモール別に検証する。
- 同一商品へ照合できた有効在庫だけを商品カードへ接続する。
- 7日以内に確認された商品を新鮮なオファーとして扱う。
- 同一商品は1モール1件、最大9件を署名付きURLで提示する。
- 検索結果、カテゴリ、別ドメイン、認証情報付きURLを商品詳細として拒否する。
- 内部診断APIは件数と状態だけを返し、商品URLやSecretを公開しない。

## モールを実稼働させる前提

次の全項目が揃うまでは、検索導線のみを提供し「商品データ連携済み」と表示しない。

1. モール、ASP、出店者のいずれかから商品データ利用許可を得る。
2. 商品名、商品詳細URL、外部商品ID、価格、通貨、在庫状態、確認日時を受領する。
3. 画像を使う場合は画像URLの転載・表示条件と有効期限を確認する。
4. HOSHILUの商品 `record_key`、または正しいASINへ照合する。
5. アフィリエイトURLを使う場合は媒体承認とディープリンク条件を保存する。
6. テスト取込後、商品URL診断が `HEALTHY` になることを確認する。

## 安全な取込単位

- 1リクエスト最大200件。
- `tenant` と `batch_id` を必須にする。
- `external_product_id` と `record_key` または正しいASINを必須にする。
- `observed_at` はISO 8601で保存し、未来日時を拒否する。
- 在庫切れ・停止・7日超のURLを公開候補から除外する。
- 未承認の追跡パラメータや推測したアフィリエイトIDを付与しない。
- 追加5モールは `data_rights_status: APPROVED` とHTTPSの `rights_reference` がないレコードを拒否する。

## 診断状態

| 状態 | 意味 | 次の対応 |
|---|---|---|
| `FEED_REQUIRED` | 照合済みの新鮮な商品が0件 | 許諾済み商品URLを取り込む |
| `MATCHING_REQUIRED` | 新鮮な商品はあるがHOSHILU商品へ未照合 | `record_key` またはASINを修正 |
| `REFRESH_REQUIRED` | 7日を超えた商品がある | URL・価格・在庫を再確認 |
| `HEALTHY` | 照合済みで新鮮な商品がある | 定期更新と失効監視を継続 |

## 追加5モールの確認事項

| モール | 人による確認が必要な項目 |
|---|---|
| ZOZOTOWN | Web媒体提携、商品フィード、画像・価格・在庫・更新頻度 |
| SHOPLIST | 正式商品URL実例、商品フィード、ディープリンク、画像利用 |
| MUSINSA | Curatorの日本向けWeb適用、商品データ利用、日本精算 |
| BUYMA | Personal Shopper API以外のメディア向けデータ提供可否 |
| SNKRDUNK | Web媒体提携、商品・相場・画像データ、ディープリンク |

## 公開判定

商品カードに表示してよいのは、商品詳細URL・商品ID・照合キー・在庫・確認日時を検証できたレコードだけとする。提携審査中、規約未確認、画像権利未確認のデータは公開しない。
