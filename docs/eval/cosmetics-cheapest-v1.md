# 化粧品 評価セット v1（最安案内）

目的：同一商品判定の正確さと、2 店以上の実価格を比べられた割合を、**別々に**測る。対象を減らして成功率を高く見せない（20 商品は固定。比べられなかった商品も分母に残す）。

## 根拠の種類（列「確認」）
- **記録**：D1 `price_observations`（2026-11-07〜11-14）の商品名・商品キー・価格を Cowork が読んだ。商品ページは開いていない。
- **ページ**：販売先の商品ページを開いて、色番・容量・JAN・商品状態を確かめた（2026-11-15 Cowork、大隆さんの許可を受けて Web で開いた。購入ボタンは押していない）。
- **ページ（JANなし）**：ページで名前・容量・単品は確認できたが JAN（または JAN と同じ商品番号）が無い。**正解には使わない**（候補のまま）。
- **未確認**：まだ何も確かめていない。

「記録」だけの行は、正解として採点に使わない（候補）。「ページ」になった行だけを正解にする。

## 採点のしかた（Codex が C-1 の前後で測る）
- **同一商品判定**：各商品について、仕組みがまとめた楽天・Yahoo! のページを、この表の「同じ商品」「紛らわしい別商品」と突き合わせる。
  - 誤った同一視（別商品をまとめた）＝ 1 件でも公開を止める。
  - 取りこぼし（同じ商品をまとめられなかった）は件数で報告。
- **比較成立率**（`item-price-in-stock-24h-direct-2m-v1`）：固定 20 商品を分母とし、**同一と確認した商品**について、在庫あり・取得から 24 時間以内・商品ページへの直リンクがある実商品価格が、異なるモール 2 つ以上そろった商品の数を分子にする。送料、支払総額、AI推定、検索結果へのリンクは使わない。同じモールの複数店舗は 1 モール。
- C-1 公開前は #795 適用後の実際の本番リビジョンを記録し、公開後も同じ固定20件、同じ商品・属性、計測回数・入口・価格の鮮度判定で再取得する。比較候補が分離されたままなら複数の候補からオファーを寄せ集めない。比較画面に渡した一つの候補グループだけを採点する。
- 本番の取得が未確認、またはタイムアウト等で判定不能なものを不成立（0件）にしない。未測定が残れば正式な20件の率と前後差は未計測。確認済み件数・成立件数・20件に対する確認できた下限、両側で測れた同一IDの内訳を分ける。1件でも誤統合が確認された場合は率と無関係に公開を止める。
- 「記録」だけの行は採点に使わない。「ページ」で確かめた行だけ。確かめた行が少ないうちは「正解 n/20 で測った」と書く。

## 前後の集計ツール（開発・QA用、読み取りのみ）

```sh
node tools/line-worker/scripts/measure-cheapest-coverage.mjs /path/to/local-packet.json
```

- パケットは `cohort_id: "cosmetics-cheapest-v1"`、`roster`（`id` が `"01"`〜`"20"` の20件）、`before`、任意の `after`。roster の各件は `verification`（商品ページで確認済みなら `page_verified`）と `target`（有効13桁 `jan` と、判明している `manufacturer_part_number`・`attributes`）を持つ。国内版・韓国版等の区別は前後で変えない。
- スナップショットは `revision`（コミットSHA）、`captured_at`（タイムゾーン付きISO時刻）、`cases`。各件は `id` と `status`（`complete`／`failed`／`unverified`）。`complete` のときだけ `measured_at` と `offers`（未確認の候補が残っていなければ空配列も可）。不明な候補を無視して `complete` にしない。
- オファーにはページで確認した同一性の根拠（`verification: "page_verified"`、`jan`・既知の型番・属性）と、`source: "REAL"`、`currency: "JPY"`、モールを示す `marketplace`、`price`、`stock_status`、タイムゾーン付き `observed_at`、署名トークンを含まない元の商品ページ `product_url` を使う。24時間判定には各件の `measured_at` を使用。比較操作で購入リンクを押さない。パケットには検索文・会員ID・購入先計測トークンを入れず、リポジトリにはコミットしない。出力は固定ID・判定・件数のみ。D1・外部API・本番KPIには書き込まない。
