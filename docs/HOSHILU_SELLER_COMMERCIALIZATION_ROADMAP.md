# HOSHILU セラー・メーカー事業化ロードマップ

更新日: 2026-07-30

## ゴール

メーカー・セラーがHOSHILUを知り、参加申請し、審査・契約・商品同期・請求・決済・
成果確認までを安全に完了できる状態を作る。

## 事業者の導線

`HOSHILUトップ`

→ `出品・商品連携を希望する方`

→ `料金・仕組み・FAQ`

→ `参加申請`

→ `受付通知`

→ `運営審査`

→ `契約条件提示`

→ `契約・決済方法登録`

→ `モール／商品フィード接続`

→ `初回商品照合`

→ `公開・KPI確認`

## Phase 1: 公開説明と連絡

- `/for-business` に参加メリット、対象事業者、料金概要を掲載
- 契約済みセラーのログインと新規申請を分離
- `/for-business/apply` に申請フォームを設置
- Turnstile、同意、入力検証、レート制限を実装
- 受付番号を発行
- 申請者へ受付通知、運営へ新規申請通知
- APIキー・パスワード・トークンを入力させない

完了条件:

- 未契約の事業者がログイン情報なしで申請できる
- 申請内容が他社へ漏れない
- 同一申請の連打・重複通知を抑止できる

## Phase 2: 審査と契約

- 事業者、店舗URL、カテゴリ、商品情報を審査
- 承認、修正依頼、却下を監査ログへ記録
- 契約開始日、導入3か月終了日、料金、成果報酬率を契約レコードへ保存
- 契約条件はコードへ固定せず、契約時のスナップショットを保持
- 電子契約サービスは候補比較後に選定

完了条件:

- 承認前の商品が公開されない
- 契約条件を後から変更しても過去請求が変わらない
- テナントをまたいで契約・KPIが閲覧できない

## Phase 3: 決済

第一候補はStripe。

- Stripe CustomerをHOSHILUの事業者IDへ関連付け
- 月額はCheckout／Subscriptionで前払い
- 成果報酬は前払い残高から帰属確定時に消化
- 法人はStripe Invoicingまたは銀行振込を選択可能
- カード情報はHOSHILUで保持しない
- Webhook署名検証とイベントIDの重複排除
- 翌利用期間の開始時点で未払いなら契約直リンクとセラー機能を停止
- 支払確認後に自動再開
- 未払い期間へサービスを提供せず、売掛債権を原則作らない
- 返金・解約・プラン変更・請求先変更を管理
- 通常解約・未使用残高は返金不可とし、二重課金・誤課金・法令上必要な場合だけ例外審査
- チャージ前に返金不可条件と規約バージョンへの同意を保存

完了条件:

- 同じWebhookを複数回受けても二重請求しない
- 支払い済み期間の途中では即時停止せず、次期開始時に未払いなら停止
- 停止後の支払確認で重複なく再開
- 請求額の根拠を事業者と運営が確認できる
- 一般セラーが管理画面から任意に返金操作できない

## Phase 4: 3か月から4か月目への移行

- 参加後3か月は月額0円＋帰属売上6%
- 4か月目の14日前に推奨プランを通知
- 商品数、帰属売上、同期負荷、分析要件で推奨
- STARTER、GROWTH、SCALE、ENTERPRISEから選択
- 固定費なしの継続希望にはPERFORMANCE ONLY 10%を提示
- 選択されない場合の扱いは契約時に明示

完了条件:

- 移行日と適用料金に曖昧さがない
- 事業者が同意する前に新料金を請求しない
- 旧プランと新プランの請求期間が重ならない

## Phase 5: 成果明細とKPI

- 表示、クリック、ほしっとく、注文帰属を事業者別に表示
- 商品小計、返品控除、対象売上、料率、成果報酬を月次明細化
- 消費税・送料を成果報酬対象から除外
- 注文者の不要な個人情報を保存しない
- 商品URL鮮度、在庫同期成功率、未充足需要を表示

## ユーザー操作が必要になる地点

実装調査とローカル開発は先に進める。次の外部操作だけユーザー確認を求める。

- Stripeアカウントの事業者確認
- 振込口座・請求書発行者情報の登録
- 正式料金、税込／税別表示、支払期限の承認
- 電子契約サービスの契約
- 本番SecretとWebhook URLの登録
- 実課金を伴う本番決済テスト
