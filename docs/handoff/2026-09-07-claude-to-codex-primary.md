## 3. いま壊れている／未確認のもの（**ここが一番大事**）

### 3.1 希望価格ウォッチ：修正済みだが本番未確認 🟡
`src/target-price-watch.mjs` は**3時間ごとに動いている**（`TARGET_PRICE_CHECK` の記録あり）。
9/7 に実データを見て2つの不具合を発見し修正した（`01b38be`）。

**不具合1: 別商品で誤通知しうる状態だった**
旧実装は「商品名の先頭12語のうち2語一致で同一商品」。実データの商品名は先頭がキャンペーン文:
```
【8/16 23:59まで まとめ買いクーポン3点以上で 10%OFF 】 java ジャバ バッグ … jv1159001
```
→ 型番 `jv1159001` が判定に入らず、「全く別のブランド レディース トートバッグ」が
「バッグ・レディース・トートバッグ」の3語一致で**同一商品と判定されていた**。
修正: キャンペーン文を捨て、型番（位置を問わず拾う）とブランド語を必ず見る。型番一致だけで確定。
型番があるのに候補名に無いときは一致率7割。迷ったら通知しない。

**不具合2: 巡回結果が残っていなかった**
「調べた」印だけで価格を残していなかった。`target_price_observations`（migration 0076）に
結果だけを残す（会員ID・検索文なし、90日保持）。理由は `NO_CANDIDATES` / `NO_MATCH` /
`ABOVE_TARGET` / `REACHED`。

**⚠️ 未確認**: 次の巡回（15:00 JST頃）まで観測記録は0件。以下で切り分ける。
```sql
SELECT reason, matched, COUNT(*) n, MIN(price_jpy), MAX(price_jpy), MAX(observed_at)
FROM target_price_observations GROUP BY reason, matched;
```
- `NO_MATCH` ばかり → 判定が厳しすぎ。`IDENTITY_MIN_RATIO`(0.5) / `IDENTITY_STRICT_RATIO`(0.7) を下げる
- `ABOVE_TARGET` → 正常（価格が届いていないだけ）
- `NO_CANDIDATES` → モールAPI側
- 0件のまま → 巡回が回っていない。`search_watch_matches` の `TARGET_PRICE_CHECK` の `matched_at` を見る

**根本原因は未着手 🔴**
3件とも `condition_snapshot.price_condition.target_product_key` が**空**。モールの商品IDが
保存されておらず、商品名だけで毎回探し直している。ここを埋めない限り「厳しくすれば取りこぼし・
緩くすれば誤通知」から抜けられない。**次の最優先実装はこれ**（クライアント側 `public/app.js` の
ウォッチ保存ペイロードに `record_key` / `asin` を載せる）。

`assets-v126/ai-search-layout-fix.css?v=127` / `search-suggest.mjs?v=2`
