## 0. ひとことで

HOSHILU の売上は 2 本です。

| 売上の柱 | 中身 | いま |
|---|---|---|
| A. モール送客 | 検索結果からモールへ移った人が買うと、アフィリエイト報酬（Amazon アソシエイト・楽天アフィリエイト・バリューコマース）が入る | 30 日でモールへのクリック 38 回。報酬額は未確認 |
| B. Seller 契約 | 掲載 1,980円／AI販促 Light 9,800円・Standard 19,800円（税込・月額、30 日無料のあと自動更新） | 外部店の契約 0 |

**人の訪問はまだ少ないが、来た人はよく検索する**（AI 検索から来た 6 セッション中 4 で検索、Google から来た 4 中 2）。なので、この 2 週間は
1. **Seller の申込を 1 件でも完了させる**（B。1 件で月 1,980〜19,800 円）
2. **人の訪問を増やす**（A の母数）
3. **本当の報酬額を毎週記録する**（何が売上に効いたかを数字で判断するため）

に集中してください。コードの変更は Claude Code が行います（§6）。

## 2. 施策（優先順）

### 2-1. Seller の申込を完了させる【最優先・売上直結】
1. **申込の詰まりを見つける**: スマホ（幅 390px 程度）と PC で `https://hoshilu.app/for-sellers` を開き、申込ボタン → フォーム → 送信の直前まで実際に操作する（**送信はしない**）。分かりにくい所・入力が多すぎる所・エラーになる所を、画面のスクショと一緒に記録する。
   - 成果物: `docs/handoff/2026-10-XX-cowork-to-claude-code-revenue.md`（§6 の書き方）。直すのは Claude Code。
2. **フォームを開いた 4 件の行方を確認**: 管理 API の相談一覧（`GET /api/admin/seller-business/inquiries`、表は `seller_business_inquiries`）で、直近 30 日に相談が入っていたかを見る。入っていて返事をしていなければ、返信の下書きを最優先で作る（送信は大隆さん）。
3. **10/3 に案内した 6 店へのフォロー**: 返信が無い店に 1 回だけ、短いフォローの Gmail 下書きを作る（2 回目以降は送らない）。書くこと: 30 日無料・開始前にカード登録と自動更新への同意が必要・売上や順位は約束しない。
4. **新しい案内**: 週 10 通の Gmail 下書き。対象・書くこと・書かないことは前の指示書 §4-1 と同じ。2 週間で 20 店。送信した店は `seller_outreach_contacts` に `SENT` で記録（メールアドレス・本文は入れない、前回と同じ）。
- KPI（毎週記録）: 下書き数・送信数・返信数・相談数・契約（トライアル開始）数・初回公開数
- 目標（2 週間、約束ではなく目安）: 相談 2 件、トライアル開始 1 件

### 2-2. 本当の報酬額を毎週記録する
- Amazon アソシエイト・楽天アフィリエイト・バリューコマースの管理画面で、**先週 1 週間のクリック数・注文（成果）数・報酬額**を記録する。Cowork が管理画面を開けない場合は、大隆さんに月曜にスクショを 3 枚だけお願いする（§7 の選択式で聞く）。
- ダッシュボード（`/admin/promotion`、7 日）のモール送客と並べ、「HOSHILU のクリック数」と「モール側のクリック数」がずれていないかも見る（大きくずれたら Claude Code へ）。
- 成果物: §4 の週次記録に 1 表。

### 2-3. 人の訪問を増やす（A の母数）
1. **AI 検索・Google に拾われる記事のテーマを選ぶ**: Search Console の「クエリ」で、表示はあるのに 10 位より下・クリック 0 の言葉を毎週 5 個選び、「その言葉で探す人が知りたい答え」を 1 行ずつ書いて Claude Code に依頼する（記事の作成・題名の変更は Claude Code）。AI 検索から来る人が一番検索するので、**質問にそのまま答える形**を優先する。
2. **SNS の本数より中身**: Threads の自動投稿は本数が多いのに人がほぼ来ていない。買い物ノートの実データ（今週値下がりした商品・いま売れている物の値段の動き）に寄せて本数を減らす案を、大隆さんに選択式で聞く（§7）。**自動投稿の追加・削除・頻度変更は大隆さんの承認が要る**。
3. **木曜の買い物ノート投稿**の反応（Instagram のインサイト: リーチ・保存・プロフィールへのアクセス・リンクのタップ）を毎週記録する。
4. **Web 広告**: お金がかかるので、Cowork は案を作って選択式で聞くところまで（§7）。出稿はしない。

### 2-4. 送客の質を見る（10/22 以降）
- 計測を直した後の 1 週間（10/16〜10/22）で、検索した人のうちモールへ移った割合と、押されたモールの順位を記録する。
- 検索した人の半分以上がモールへ移らないなら、検索結果の画面で迷っている所を実際に操作して探し、Claude Code へ依頼する（2-1 と同じ書き方）。

## 3. やらないこと
- 料金・規約・特商法の文言を変える（大隆さんの承認が要る。直すのは Claude Code）
- 売上・順位・人数の約束、「最安」「限定」「必ず」などの根拠の無い表現
- Gmail を送信する（下書きまで。送信は大隆さん）
- SNS の自動投稿を足す・消す・頻度を変える、広告を出す、お金がかかる契約をする（大隆さんの承認が要る）
- コード・本番設定（vars）・本番 DB を直接変える（Claude Code に依頼）
- 店の連絡先・メール本文・利用者の検索文・会員情報を、リポジトリ・ログ・公開の場所に書く

## 4. 毎週のリズム
- **月曜（午前）**: 数字を `docs/handoff/2026-10-XX-cowork-revenue-weekly.md` に追記する（1 週 1 節）
  1. ダッシュボード 7 日（訪問・検索開始・検索成功・モール送客・流入元の上位 5）
  2. アフィリエイト 3 社の先週のクリック・成果・報酬額（2-2）
  3. Seller: 下書き・送信・返信・相談・契約・初回公開（2-1）
  4. Search Console: 過去 7 日のクリック・表示・平均順位、上位クエリ 5（2-3）
  5. Instagram 木曜投稿の反応（2-3）
  6. 今週やること 3 つ
- **火〜金**: 案内とフォローの下書き、申込の詰まりの記録、Claude Code への依頼

## 6. Claude Code に頼むこと
`docs/handoff/YYYY-MM-DD-cowork-to-claude-code-revenue.md` に書く。1 件ごとに次の 4 行を必ず入れる:
1. **どこで**（URL・端末・画面幅）
2. **何をしたら**（操作の順番）
3. **何が起きたか**（スクショ・表示された文言）
4. **どうなってほしいか**

Claude Code は毎朝 8:51 の点検でこのファイルを確認し、直したら同じファイルに結果を書き足す。急ぎのときは大隆さんから Claude Code に「Cowork の依頼書を見て」と伝えてもらう。

頼むものの例: 申込フォームの直し、記事の作成・題名の変更、計測のずれの調査、SNS 投稿の中身の差し替え（大隆さんの承認後）。

## 7. 大隆さんに選択式で聞くこと（最初の週にまとめて 1 回）
1. アフィリエイト 3 社の報酬の確認: (a) Cowork が管理画面を見てよい (b) 大隆さんが毎週月曜にスクショを送る (c) 当面見ない
2. Threads の自動投稿: (a) 本数を半分にして買い物ノートの実データに寄せる (b) 今のまま (c) いったん止める
3. X の自動投稿: (a) 買い物ノートの木曜枠だけ再開 (b) 停止のまま
4. Web 広告の少額テスト: (a) 月 1 万円 (b) 月 3 万円 (c) まだやらない（媒体は Google 検索広告か Instagram を想定。出稿は承認後に Claude Code と準備）
