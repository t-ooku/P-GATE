## 0. 大隆さんの決定（原文のまま）

> ターゲットを主婦層25〜40代に変えるべきだと思う。geminiや検索エンジンとの違いは、希望価格ウォッチやクーポン通知だから。それ以外は、あまりgeminiやGoogleと変わらない気がする。今後のai女優も、最初の女優だね。

要点は3つ。①ターゲット = 主婦層 25〜40代。②差別化の主軸 = 希望価格ウォッチとクーポン通知（「まとめて探す」は維持）。③AI女優 = **v1（最初の女優）に統一**。

## 1. AI女優ラインの変更

| 項目 | 変更前（08-22 / 08-29 指示） | 変更後（本書） |
|---|---|---|
| 毎日20:15 JST の X / Instagram リール | **v2**（22歳設定）を毎日1本 | **v1**（hoshilu-approved-model-reference-v1.jpg）を毎日1本。v2 の毎日枠は**停止** |
| v1 の位置づけ | 30〜50代向けの補助ライン | **主ライン**。ターゲット表記を「25〜40代の主婦層」に更新（権利台帳の参照画像は変更なし） |
| v2 の扱い | 主ライン | 承認済み在庫は捨てない。**新規生成は行わない**。既存在庫は「10〜20代向け補助」として、大隆さんの個別承認があった日のみ 20:00 非動画枠等で使用 |
| トーン | v1: 丁寧め／v2: 友達口調 | v1 のまま丁寧め。ただし「家計・買い替え・セール見逃し防止」の生活導線の言葉を優先（下記 §2） |

実装上の作業:

1. `social-autopilot.mjs` の毎日枠の参照ライン（persona/ライン指定・キャプションのトーン）を v2 → v1 に切り替える。`identity_consistent` は v1 ライン内で適用。
2. 承認済み v1 在庫が **7日分未満**なら、Runway 新規生成は従来の上限（月 6,000 クレジット、週2〜3本）の範囲で **v1 参照画像**から生成する（新規生成ジョブは Claude の submit-runway-job、権利承認は大隆さん — 役割分担は変更なし）。在庫が揃うまでの間は、承認済み v1 素材の再編集と、v2 の既存在庫を「補助」として使うことを認める。
3. 切替日は **v1 在庫が 3日分以上そろった日**とし、切替日と初回投稿 URL を `docs/handoff/` の日次セルフチェックに記録する。

## 2. 投稿テーマの配分（08-29 の5テーマ配分を置き換え）

主訴求の配分は **まとめて探す 10% / 希望価格ウォッチ 50% / クーポン・セール通知 40%**（2026-09-04 22:10 JST 大隆さん指示で 40/30/30 から変更。差別化点に投稿を寄せる）。

| 主訴求 | 配分 | 投稿文の核（v1 トーン） | 主リンク |
|---|---|---|---|
| まとめて探す | 10% | 「Amazon・楽天・Qoo10 を1つずつ開かなくていい」「欲しいもの、まとめて探す。」 | `/` |
| 希望価格ウォッチ | 50% | 「今すぐ買わないものは『この価格になったら教えて』に入れておく」「安くなったら HOSHILU が知らせる」 | `/#mywatchTitle`（会員登録導線） |
| クーポン・セール通知 | 40% | 「セールとクーポン、見逃してた…をなくす」「よく使うモールのセールだけ通知」 | `/#saleCenterTitle`、ショップページ `/shop/<slug>`（🎟 クーポンがある時） |

- 週7投稿なら **1 / 3 / 3**（端数は希望価格ウォッチへ）。10投稿なら 1 / 5 / 4。
- 「写真・スクショ・投稿URLから探す」「曖昧検索」「BUZZ」は**まとめて探す**の中の題材として扱う（独立枠にしない）。
- 主婦層 25〜40 の生活導線の題材を優先する: 日用品・キッチン・子ども用品・コスメ・衣類の「同じものを安く」「買い替え時期」「セール前に価格を入れておく」。
- 各投稿に UTM（`docs` の `hoshilu_utm_link_spec`）と、クリエイター計測が必要な場合は `creator_id` を付ける（既存仕様どおり）。

## 2-a. 希望価格ウォッチ推しリール（v1）— 2026-09-04 作成済み

- `scripts/build-watch-reel.py` が v1 参照画像＋既存音源から ffmpeg で 9 秒の縦動画を作る（Runway 課金なし）。`.github/workflows/build-social-reel.yml` がスクリプトの push で MP4 を再生成し `public/social/hoshilu-ai-actress-watch-v1.mp4` としてコミット・デプロイする。
- **注意（2026-09-04 に実際に起きた）**: スクリプトの push は ci.yml も起動する。build-social-reel.yml が MP4 をコミット・デプロイした後に、ci.yml の deploy（MP4 を含まない元の commit）が後から走ると、hoshilu.app/social/ から MP4 が消える。リール生成後は、ブランチ先頭を含む push（文書更新でよい）をもう1回行って再デプロイすること。恒久対応（ci.yml の deploy がブランチ先頭を取り直す）は Codex 作業。
- 投稿文（X / Instagram 共通）: 「今すぐ買わないものは、『この価格になったら教えて』に入れておくだけ。Amazon・楽天・Qoo10などの価格をHOSHILUが定期確認して、希望価格になったら通知します。セールを待つあいだ、何度も見に行かなくて大丈夫。」 リンクは `/#mywatchTitle` に utm_campaign=watch_reel_v1。
- Codex 作業: social-autopilot の DAILY 枠に `hoshilu_ai_actress_watch_v1`（media_url https://hoshilu.app/social/hoshilu-ai-actress-watch-v1.mp4、topic=希望価格ウォッチ）を追加し、配分 10/50/40 の「希望価格ウォッチ」枠の初回素材にする。

## 4. KPI（経営 KPI の北極星候補）

以下を `/admin` の実数 KPI に並べ、北極星の差し替え候補として週次で見る（growth_events の allowlist にあるイベントを使う。無いものは追加してから）。

- 希望価格ウォッチ登録数（新規／累計）
- クーポン閲覧数・クーポン遷移数、ショップフォロー数
- 通知からの再訪数（希望価格通知・セール通知の別）
- 既存: 会員登録 CV、検索→販売ページ遷移

## 5. 既に本番へ入っている UI 側の対応（参考）
