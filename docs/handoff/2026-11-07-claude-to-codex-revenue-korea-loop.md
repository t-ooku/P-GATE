### T0.（P0・最優先・2026-11-07 追加）写真検索で Gemini が落ち、英語のカテゴリ語だけで検索している
- **どこで**: 本番の写真検索（モバイル）。大隆さんの実機、2026-11-07 09:13 JST ごろ。
- **何をしたら**: 机の上の実物のトラックボールマウス（赤玉・黒・親指操作、エレコム EX-G PRO 系）を撮って検索。
- **何が起きたか**:
  - 検索語が **「mouse Computer」**（英語・ブランド名なし）。結果 33 件の先頭は ¥464 の LED 無線マウス（カテゴリ違い）。House-Mouse のグリーティングカード（「mouse」の文字一致）も出た。本命の商品は出なかった。
  - 同じ写真で Google レンズは 1 件目に「エレコム トラックボール EX-G P…」を価格・店名つきで表示。
  - 「mouse Computer」は `weakGoogleVisualBestGuessAnalysis`（`tools/line-worker/src/search-input-analysis.mjs:371`）の出力の形（best-guess ラベル＋エンティティ 1 つ）と一致する。つまり **Gemini の解析が主・予備モデルの両方で失敗し、`GOOGLE_VISION_BEST_GUESS_FALLBACK` で救済された**可能性が高い（推定。本番ログで確認すること）。
  - 疑わしい点（推定・未確認）: `GEMINI_IDENTIFY_GROUNDING=true` のとき `responseMimeType`/`responseSchema` を外しているため JSON 以外の応答で解析失敗→救済に落ちていないか。14 秒＋9 秒のタイムアウトに当たっていないか。救済の弱い経路で、Vision の web_entities に含まれるブランド（Elecom 等）や「Trackball」を捨てていないか。
- **どうなってほしいか**:
  1. 本番の識別テレメトリ（provider・diagnostic コード）で、写真検索のうち `GOOGLE_VISION_*_FALLBACK` に落ちている割合を直近 7 日で出す（読み取りのみ）。この 1 件の provider も特定する。
  2. 原因を直す（`/investigate` → 修正 → テスト）。救済経路でも、Vision のエンティティにブランド・具体カテゴリ（例 Elecom・Trackball）があればそれを優先し、日本のモールで当たる語（例「エレコム トラックボール」）にする。英語の汎用語（mouse・computer など）だけの検索語は出さない。
  3. 回帰テスト: 実物写真の固定セット（トラックボール 1 件を含む）で「検索語にブランドかカテゴリが入る」こと。可能なら Teacher Dataset の失敗記録にこの 1 件（入力の種類・期待商品・実結果）を入れる（D1 書き込みは承認依頼を出してから）。
- **判定**: 同じ写真の再検索で本命（エレコム トラックボール）が上位 3 件以内。7 日間の救済経路の割合が下がる。
- **T2〜T4 より先にやる理由**: 入口を増やしても、写真検索がレンズに 1 発で負ける状態では、来た人を逃すだけになる。

### T1. アフィリリンクの付与状況を一覧にする（読み取りのみ・最優先）
- **2026-11-08 追記（判明済み）**: `tools/line-worker/wrangler.jsonc` で `VC_GO_REFERRAL_ENABLED: "false"`・`VC_RAKUTEN_GO_REFERRAL_ENABLED: "false"`。2026-09-02 に「Qoo10 のリンクが別モールへ着地する」報告で止めたまま（`src/index.mjs` の `/go` 処理）。そのため **/go 経由の Yahoo!・Qoo10・ハンズ・マツキヨ・SHEIN への送客にバリューコマースの ID が付いていない**。実際にバリューコマースは 11/1〜11/8 でクリック 0・注文 0・0 円（大隆さんのスクショ）。
  - やること: (1) 2026-09-02 の「別モールへ着地」不具合を再現する（Qoo10 の商品 URL・検索 URL それぞれを referral で包み、実際の着地先を確認）。(2) 正しく着地するモール（例: Yahoo!）だけを許可リストで有効化できるようにする（モール単位のフラグ）。(3) フラグを `true` にするのは大隆さんの承認後（送客先が変わるため）。承認依頼を handoff に書く。
  - 判定: 有効化後 7 日でバリューコマースのクリックが 0 でなくなる。ホシル側の marketplace_click（Yahoo!・Qoo10）と桁が合う。
- どこで: モール遷移リンクを組み立てているコード（marketplace_click を出す箇所）。
- 何を: Amazon・楽天・Yahoo!・Qoo10・ZOZOTOWN・SHEIN の遷移 URL に、アフィリ ID（Amazon tag／楽天 hgc／バリューコマース sid・pid／Qoo10 Share Affiliate）が実際に付いているかを、本番の実 URL で 1 件ずつ確かめる。
- 出力: `docs/handoff/2026-11-XX-codex-affiliate-link-audit.md` に表（モール／ID 付与あり・なし／確認した URL の形（ID は伏せる））。付いていないモールがあれば、それが「報酬 0」の原因候補として先頭に書く。
- 判定: 送客上位 3 モール（現状 楽天・Yahoo!・ZOZOTOWN）＋ Qoo10・Amazon が「付与あり」なら完了。
