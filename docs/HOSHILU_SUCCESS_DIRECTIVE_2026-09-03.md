# HOSHILU 成功実行指示書（Cowork主幹・完全改訂版）2026-09-03

大隆さんから 2026-09-03 12:00 JST 頃に受領した指示書の保存版。Cowork（Claude）が
主幹として横断的に担当する。原文の要点をそのまま保持し、実装状態の記録欄を末尾に置く。

## 1. 最終目的

HOSHILU を「欲しいけど、名前が分からない」から始められる商品検索として成功させる。
成功体験は「見つかった」「すぐ買える場所が分かった」の2つ。

## 2. 最重要ユーザー心理（最短導線）

これ欲しい → HOSHILUで探す → これじゃない？ → Amazon / Qoo10 / 楽天 / Yahoo! など → 購入先へ。
禁止: 商品名の再入力、無意味な確認画面、不要なモーダル、説明ページへの強制遷移、登録しないと検索できない、
モールへ行く前の余計な操作、API都合で正解モールを隠す。

## 3. 絶対原則: AIは理解、HOSHILUは探す

AI: 意図理解、商品候補、ブランド/型番候補、特徴抽出、多言語検索語、SNS/画像からの候補推定。
HOSHILU: 実商品、実際の購入先、実在URL、実取得価格、モール比較、購入導線。
AIは URL・価格・在庫・販売状態 を捏造しない。

## 4. 現在最大のP0

Instagram/TikTok で見た商品が Amazon・Qoo10・SHEIN・ブランド公式の商品なのに、楽天や Yahoo! の商品しか
表示されない状態は許容しない。「APIがない = そのモールを消す」は禁止。

## 5. 新検索方式

STEP1 入力理解（文章・曖昧・一言・写真・スクショ・Instagram/TikTok/X URL・色・サイズ・素材・用途）
STEP2 AIが商品候補を特定（商品名・ブランド・型番・カテゴリ・色・素材・特徴・別名・英語名・韓国語/中国語候補・想定販売先）
STEP3 HOSHILUが購入先を探す（Amazon, Rakuten, Yahoo!, Qoo10, SHEIN, ZOZOTOWN, LOFT, Hands, Matsukiyo, @cosme, ABC-MART, BUYMA, SNKRDUNK）

## 6. モール表示方式

A: 実商品取得可能 → 商品カード（画像・商品名・価格・店舗・URL）。
B: API取得不可だが検索可能 → モールを隠さず「Amazonで見る」「Qoo10で見る」等。AI特定の商品名・ブランド・型番を
検索語に自動セットしたモール検索結果へ直接飛ばす。再入力させない。
C: 完全非対応 → 可能な限り検索リンク導線を用意し、Cを減らす。

## 7. Amazon / Qoo10 最短導線

正解候補の商品カード直下に「Amazonで見る」「Qoo10で見る」「楽天で見る」「Yahoo!で見る」等を即表示。
表示順は固定せず、正解可能性・販売可能性・SNS流通傾向・利便性で決める（Instagram由来の韓国コスメなら Qoo10 → Amazon → 楽天 → Yahoo! でもよい）。

## 8. タップ数ルール

商品候補表示後、原則1タップでモールへ。検索 → 商品候補 → モール を2操作程度に。

## 9. 商品候補とおすすめを混ぜない

① これを探していませんか？（本命） → ② 買える場所 → ③ 似ている商品。

## 10–12. 検索品質・順位・価格表示

カテゴリ違いを上位に出さない（本革トート→財布/合皮を出さない等）。順位はモール都合・API可否より「探している商品に近いか」。
API価格とAI推測価格を分離し、「最安」は同一商品・同一条件・取得時刻が揃う時だけ。

## 13–17. トップページ

説明サイトではなく検索開始装置。ファーストビュー: 「欲しいけど、名前が分からない。」/ 写真・スクショ・SNS・一言から探せます /
「何が欲しいの？」/ 写真・スクショ・SNS / 最大13モール。順番: 検索 → 写真・スクショ・SNS → 検索例 → 検索結果例 → BUZZ →
SALE RADAR/通知 → 13モール → 仕組み → NEWS → SEO → フッター。MARKETPLACE COVERAGE / SEARCH AGENT / DISCOVERY / 長い説明は後ろへ。
検索例（タップで即検索）: インスタで見た白いバッグ / 韓国っぽいシルバーリング / このスクショのマットレス / 自立する本革トート /
この靴に似たもの / SNSで見たピンクのリップ。

## 18–21. 登録は後

検索 → 発見 → 欲しい → 保存したい → 登録。「♡ ホシっとく」「🔔 値下がり/新商品を知らせる」を押してから無料登録。登録モーダルは最短。

## 22–23. HOSHILU BUZZ

ランキングではなく「新しい検索のきっかけ」。若者向けには韓国関連を最低1件。BUZZ商品タップ → 即HOSHILU検索 → Amazon/Qoo10導線を短く。

## 24–27. SNS

主テーマを「これ、どこの？」に。Reel構成: Instagramで発見 → これどこの？ → スクショ → HOSHILU → これかも → Qoo10/Amazon → 見つけた →
名前が分からなくても、ホシル → hoshilu.app。目的は「HOSHILUで1回検索させること」。

## 28–29. SEO

「HOSHILUとは」ではなく悩み起点（インスタで見た服を探す方法 / スクショから商品を探す / 韓国コスメ 名前 分からない 等）。
記事内に「この画像から探す」「SNS URLから探す」「HOSHILUで検索する」を配置。

## 30–31. 広告

検索体験が不十分なまま大量投入しない。無料SNS・SEO・BUZZ・オーガニック・少額テストで検索CVを確認。
クリエイティブ優先: 「インスタで見たこれ、名前が分からない。」→「Amazon？Qoo10？楽天？どこで売ってる？」→「今何がバズってる？」

## 32–35. KPI

流入 → 検索 → 検索成功 → 商品クリック → モール遷移 → ホシっとく → 登録 → 通知 → 再訪 → 購入先送客。
必須指標: 訪問者数、検索開始率、Search Success Rate、商品クリック率、モール遷移率、モール別クリック（Amazon/Qoo10/SHEIN/楽天/Yahoo!）、
ホシっとく率、登録率、通知設定率、7日再訪率、0件率。新KPI: Search to Mall Time / Search to Mall Taps。
初期目標: 訪問→検索 30%、Search Success 70%、検索→商品クリック 20%、検索→登録 5%、登録→通知 50%、7日再訪 15%。推測値を実績として報告しない。

## 36–38. モール別管理・失敗分析・Teacher Dataset

管理画面で13モールを一覧化（API可否・検索リンク可否・認証・最終成功・表示件数・クリック・エラー）。失敗検索を毎日記録し Teacher Dataset へ
（入力・期待商品・実結果・誤り・修正・再テスト・PASS/FAIL）。

## 39. P0優先順位

P0-0 Amazon/Qoo10/SHEIN等の商品をAPI都合で消さない → P0-1 商品特定後1タップでモールへ → P0-2 AI商品候補→13モール検索方式 →
P0-3 本命と類似の分離 → P0-4 検索品質 → P0-5 検索結果UI → P0-6 トップ簡素化 → P0-7 ホシっとく→登録 → P0-8 通知→登録 → P0-9 完全KPI。
その後 SEO/SNS。広告拡大は最後。

## 40–44. 原則

30日間は大型新機能を増やさない（検索改善・モール対応・UI・CV・KPI・バグ・セキュリティ・障害は例外）。UIは邪魔をしない、迷ったら削る。
モバイル最優先（320/375/390/430px で文字切れ・ボタン切れ・重なり・横はみ出し・閉じられないモーダルを禁止）。
差別化: 曖昧な欲しい → 商品を特定 → 買える場所へ最短で。収益のために購入導線を邪魔しない（ユーザー増 → 検索増 → モール遷移増 → Affiliate → Seller Priority → Premium → Business）。

## 56. 作業の進め方（2026-09-03 大隆さん指示「一つ一つが手間と時間かかる」）

同じ失敗の型を1日で4回繰り返した。**部品は確認したが、経路を確認しなかった。**

- セラー向けSEO記事6本を出したが、着地先の相談フォームはD1にテーブルが無く送信が失敗していた
- そのフォームは問い合わせが入っても通知が飛ばなかった
- そのフォームは確認欄（Turnstile）が表示されず、そもそも送信ボタンが機能しなかった
- Google広告のキーワード12個のうち4個は検索ボリュームが無く、案内した管理画面URLは404だった

いずれも大隆さんに手を動かしてもらってから発覚した。往復のたびに時間が消える。以後こうする。

1. **大隆さんに何かを頼む前に、経路を端から端まで自分で通す。** 保存先のテーブルがあるか、
   コードが本番に出ているか、通知先が設定されているか、リンクが実際に開くか。1つでも
   未確認のまま頼まない。
2. **外部サービスに渡す値は、渡す前に実在を確かめる。** キーワードは検索ボリューム、URLは
   実際に開けるか、画面の場所はメニューの階層まで。
3. **自分で操作できないもの（ブラウザ実機など）は、最初から失敗する前提で作る。**
   動かなかった時に詰まらない逃げ道を実装に含める。あとから足すと往復が増える。
4. **同じ不具合を2回追って再現できなければ、原因追及をやめて設計を変える。**
   3回目の推測は時間の無駄。
5. **大隆さんへの依頼は1回にまとめる。** 小出しにしない。
6. **報告は「実数」「今日直したこと」「大隆さん作業」に絞る。** 経過の説明は書かない。

## 最終命令

機能が多い検索サイトから、欲しいものに最短でたどり着けるサービスへ。最優先は「Amazon・Qoo10・SHEIN等をAPI制約で消さない」と
「正解商品から購入先へ1タップ」。トップ改修より先に完成させ、その後 検索品質 → 検索結果UI → トップUI → 登録CV → 再訪 → SEO → SNS → 広告。
