# HOSHILU SNS成果計測 棚卸し（2026-08-02）

## 結論

投稿メタデータ、UTM、サイト内のランディング・検索開始・検索完了・ほしっとく保存・モール送客、QA判定は既に保存できる。媒体側のリーチ等、無料登録、問い合わせ、成約は投稿単位で自動結合できない。未取得値は `0` ではなく `未取得` とする。

本番D1の確認時点では `growth_events` に231件あり、QAは別分類済み。ATTRIBUTEDはランディング7件、投稿UTMまで判別できたものは1件、プロフィール共通導線 `link_in_bio` は5件。PUBLISHEDは16投稿、全件に媒体投稿ID、11件に計測リンクがある。

## 項目別の取得可否

| 項目 | 現状 | 保存元・不足 |
|---|---|---|
| 媒体・投稿日時・企画・CTA | 一部取得可 | `social_post_queue` に媒体・公開日時・本文・campaign/content。CTAと企画は専用列がなく本文・UTMから推定 |
| 投稿URL | 一部取得可 | 媒体投稿IDは全公開投稿にあるが、正規の公開URL列はない |
| UTM | 取得可 | 投稿リンクと `growth_events` の source/medium/campaign/content |
| リーチ・表示回数 | 未取得 | X/Instagram等の媒体インサイトAPIまたは公式画面からの取込が必要 |
| 保存・シェア・コメント | 未取得 | 同上。サイト内シェア開始は取得可能だが媒体シェアとは別指標 |
| プロフィール閲覧・リンククリック | 未取得 | 媒体インサイトが必要。HOSHILU到達は `landing_view` で取得可能 |
| 検索開始・検索完了 | 取得可 | `growth_events`。UTM別・QA除外で集計可能 |
| 無料登録 | 未取得 | LINE/メール登録成功イベントが `growth_events` にない |
| モール送客 | 取得可 | `marketplace_click`。現状の媒体定義は主要4モールのみでYahoo!・ファッション5モールが空分類になる |
| 問い合わせ | 未取得 | 問い合わせ完了イベント・保存先がない |
| 成約 | 未取得 | モール側コンバージョン/アフィリエイト成果との投稿UTM結合がない。推測禁止 |

## 現状の制約

- UTMは初回ページ表示時のURLから取得し、ページ遷移・再訪をまたぐ永続化はしていない。
- Instagramは本文に長いURLを出さずプロフィール導線を使うため、共通 `link_in_bio` では投稿別の帰属ができない。
- `growth_events` は個別セッションIDを持たず、ファネル各段階を同一利用者として結合できない。
- QA除外は source が `codex` / `test` / `qa`、mediumが`qa`、campaignに`acceptance` / `test`を含む場合。社内アクセスを網羅する専用分類はない。
- 既存CSVは空欄を許容するが、集計コードは欠損値を0へ変換するため「未取得」と実績0を区別できない。
- 週次上位3・下位3、前週比、原因仮説、残す/止める/試す型の自動レポートは未実装。

## 指標定義

- 投稿あたり反応 = `(保存 + シェア + コメント) / 投稿数`
- CTR = `リンククリック / 表示回数`
- 登録CVR = `無料登録 / リンククリック`
- 送客CVR = `モール送客 / 検索開始`
- 前週比 = `(当週 - 前週) / 前週`。前週が0または未取得なら `算出不可`
- 分子・分母のどちらかが未取得なら率も `未取得`
- QA・社内アクセスは全実績、率、ランキングの分子・分母から除外

## 外部設定なしで実装できる範囲

1. 投稿成果スナップショット用D1テーブルを追加し、未取得をNULLで保持する。
2. CTA・企画・正規投稿URLを投稿単位で明示保存する。
3. Yahoo!ショッピングとファッション5モールを `marketplace_click` の分類対象へ追加する。
4. 登録成功・問い合わせ完了イベントを、個人情報を保存せず追加する。
5. 社内/QA分類を明示入力できる仕組みを追加し、週次SQLで除外する。
6. 前週比、投稿あたり反応、CTR、登録CVR、送客CVR、上位/下位3件を算出する週次レポートを作る。

## 承認・外部設定が必要な項目

| 項目 | 必要な判断・操作 |
|---|---|
| Xインサイト | 対象APIプラン、読み取り権限、費用の承認。既存投稿資格と取得可能指標の確認 |
| Instagramインサイト | Meta Graph APIのInsights権限、Business/Creator接続、長期トークン運用の承認 |
| TikTok/YouTube | アカウント接続、Analytics API権限、対象投稿ID連携の承認。現在は自動投稿自体が未設定の媒体を含む |
| プロフィールリンク | 投稿別リンク/ランディングを使うか、共通プロフィール導線のまま媒体単位帰属に留めるかの判断 |
| 社内アクセス除外 | 社内端末の明示フラグ、専用QA URL、または除外識別方式の承認。IP保存は行わない |
| 成約 | 各モールの公式成果レポート/APIとUTM・subidの利用条件、個人名義アフィリエイト口座との整合確認 |

## 週次報告の固定構成

1. 当週/前週の投稿数と主要ファネル
2. 上位3投稿・下位3投稿（未取得指標を0扱いしない）
3. 企画、冒頭、形式、CTA、投稿時刻、媒体の差による原因仮説
4. 翌週に残す型、止める型、試す型
5. 欠損データ、QA/社内除外件数、計測障害
